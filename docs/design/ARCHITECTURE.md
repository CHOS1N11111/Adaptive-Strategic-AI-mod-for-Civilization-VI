# 架构与路线图

> 分类：系统设计 | [返回文档索引](../README.md)

## 1. 当前版本审计（0.3.0）

当前 Mod 已包含三层：

1. `Core/01_Difficulty.sql`：移除神级额外移民，并设置随时代累积的静态 AI 难度倍率。
2. `AI/*.sql`：调整经济、胜利、军事、伪产出和动态策略对应的 `AiLists`。
3. `Lua/AdaptiveStrategicAI.lua`：每隔固定回合比较 AI 与存活人类玩家，保存总分及科技、文化、帝国支柱状态，并激活追赶或巩固策略。

当前总分权重为科技 20%、市政 18%、科技产出 12%、文化产出 12%、城市 10%、人口 15%、军力 13%。各项比值限制在 55% 至 145%，军力对总分的贡献上限为 120%。全局追赶进入/退出阈值为 90%/96%，巩固为 115%/108%；科技、文化、帝国还有独立阈值。

### 1.1 已有优点

- 已从单一总分扩展到独立支柱。
- 有进入/退出双阈值和玩家属性持久化。
- 默认动态层主要激活 AI 策略，没有直接刷兵或复制玩家产出。
- 有分项日志和离线数据库验证工具。
- 神级额外移民已去除，减轻原版前期失衡。

### 1.2 关键问题

- **静态与动态混合**：随时代增长的神级倍率会无条件强化所有 AI，可能独立制造后期失控，无法证明动态控制器有效。
- **回合未归一化**：第 35 回合开始、每 5 回合检查，在不同游戏速度下代表不同的实际发展阶段。
- **快照噪声**：没有指数平滑、变化率和最短驻留；一次战争损失或产出变化可能误触发。
- **参考模型单一**：以存活人类平均值作为唯一标尺，不能判断世界分布、AI 是否已形成真实胜利威胁，也不适合未来多人类玩家。
- **总分可互相掩盖**：科技、文化、军力和扩张仍能在总分中互相抵消。
- **军力测量粗糙**：只累加基础强度，忽略生命、升级、兵团/军队、单位角色、战略资源、位置、维护费和战争结果。
- **基础设施代理有限**：改良数量不能完整反映住房、宜居度、区域槽位、贸易容量、建筑和可工作地块质量。
- **所有落后者都可能追赶**：这会趋向同质化，并让整个世界同时围绕玩家伸缩。
- **执行验证不足**：策略激活日志不能证明对应列表被引擎消费，也不能证明城市、行动或胜利项目实际改变。
- **性能风险**：定期遍历全部地图地块、科技和市政，对大图和多文明可能增加回合开销。

## 2. 目标架构

```text
游戏状态
   |
   v
感知器 Sensors
   |  存量、流量、趋势、地图/战争/胜利上下文
   v
归一化特征 Feature Store
   |  游戏速度换算、平滑、缺失值与置信度
   v
诊断器 Diagnoser
   |  能力健康度 + 胜利威胁度 + 可修复性
   v
控制器 Controller
   |  竞争者选择、状态机、预算、滞回、冷却
   v
执行器 Actuators
   |  Strategies / AiLists / Operations / PseudoYields
   v
遥测与验证 Telemetry
      输入 -> 决策 -> 实际行为 -> 结果
```

### 2.1 感知器

每个 AI 保存以下类别，而不是只计算一次性总分：

- **知识**：已完成科技/市政、每回合科学/文化、加速触发趋势。
- **帝国**：城市、人口、住房压力、宜居度、区域与建筑、改良、可工作地块、贸易容量。
- **经济**：生产、金币余额与收支、单位维护、战略资源、建造队列瓶颈。
- **军事**：有效战力、单位角色和时代、升级率、生命、兵团/军队、敌我损失、行动与攻城结果。
- **胜利**：宇航中心/项目、旅游与游客、原始首都、宗教传播等实际里程碑。
- **上下文**：地图海陆比例、邻居、可定居地、战争、外交、时代、灾害和游戏速度。

高成本传感器分批缓存；地图改良等数据不应为每个玩家重复全图扫描。

### 2.2 参考模型

同时保留三种参考：

- **人类参考**：回答“玩家是否已把对手甩开”。
- **世界分布**：中位数、上四分位和最强竞争者，避免平均值被异常文明扭曲。
- **自身趋势**：回答 AI 是正在恢复、停滞还是恶化。

AI 不需要被强制拉回玩家分数。诊断结果分成两个正交维度：

- **能力健康度**：经济与决策链是否存在可修复短板。
- **胜利威胁度**：是否能在合理时间内推进某条胜利路线或形成军事威胁。

一个分数落后的 AI 仍可能因旅游或首都战争成为威胁；一个产出领先的 AI 也可能没有任何胜利转化。

### 2.3 控制器

建议状态：

- `OBSERVE`：无干预，继续收集趋势。
- `RECOVER_<PILLAR>`：只修复明确支柱，可同时存在有限数量但受总预算约束。
- `CONVERT_<VICTORY>`：能力足够但胜利转化不足，强化项目、单位编成或行动。
- `PRESS_ADVANTAGE`：领先且有机会取胜，减少低价值分散建设，保持其威胁；不是削弱状态。
- `COOLDOWN`：退出后暂不重新进入同类状态。

控制器需要：

- 以标准速度等效回合定义检查间隔、最短驻留和冷却。
- 进入/退出双阈值，并结合连续多个样本或平滑值。
- 每个 AI 的干预算上限，防止同时堆叠过多权重。
- 全局竞争者名额。优先帮助仍有领土和发展基础、且短板可修复的 AI；不自动救回全部濒亡文明。
- 保留文明风格的乘数或禁用项，避免所有 AI 使用相同恢复路线。

### 2.4 执行器

执行器按风险从低到高分层：

1. 建造专精、项目、科技/市政、区域与建筑偏好。
2. 改良、贸易、定居、住房和防御等伪产出。
3. 单位角色、行动类型、目标与行为树触发。
4. 可选的静态难度曲线。
5. 可选且明确标注的直接补助模式。

默认发布只使用前三层。每个执行器都要有“预期行为”和“可观测结果”，例如激活贸易恢复后，不只看状态，还检查路线容量、商人数量和已建立路线是否增长。

### 2.5 遥测

每次评估至少记录：

- 游戏回合、标准速度等效回合、文明和难度。
- 原始指标、平滑指标、参考分布和置信度。
- 进入/退出原因、阈值、状态剩余时间、干预预算。
- 实际激活的策略和列表。
- 后续窗口内的城市建造、单位编成、战争和胜利里程碑变化。

日志必须区分“系统要求 AI 偏好某项”与“AI 实际完成某项”。

## 3. 静态难度层的处理

当前神级随时代倍率应从动态决策层拆出，形成可独立选择和 A/B 测试的配置：

- `Vanilla baseline`：保留原版持续倍率，仅移除或恢复开局资产供比较。
- `Smoothed baseline`：较弱前置资产、有限且透明的时代曲线。
- `Decision-only`：评估实时控制器时不额外叠加本项目时代倍率。

在动态决策尚未经过基准测试前，不应同时改静态倍率和策略阈值，否则无法判断结果来自哪一层。

## 4. 兼容性所有权

| 层 | 本项目计划所有权 | 与其他全面 AI Mod 的关系 |
| --- | --- | --- |
| 感知、评分、日志、状态属性 | 完整拥有 | 通常可共存，但事件与性能仍需测试 |
| 自定义 Strategies / AiLists | 完整拥有 | 名称可隔离，最终系统权重会叠加 |
| 原版 PseudoYields / build lists | 有限修改 | 极易与 Real Strategy、RHAI、AI+ 重叠 |
| Operations / behavior trees | 分阶段有限修改 | 高冲突，不默认承诺兼容 |
| 难度倍率与开局单位 | 可选模块 | 与任何难度 Mod 重叠 |
| DLL 战术与寻路 | 无所有权 | 当前不可修改 |

短期发布应声明与全面 AI 行为 Mod 不兼容。以后若支持 RHAI，应制作只保留感知与控制器、调用其已有执行层的专用配置，而不是让两套权重静默叠加。

## 5. 分阶段路线图

### 阶段 0：冻结行为，建立基线

- 只完善日志与固定种子采集。
- 将静态时代倍率与动态控制器分开开关。
- 记录原版、当前 0.3.0 和 Decision-only 三组结果。

### 阶段 1：修正感知与时间

- 全部间隔按游戏速度归一化。
- 加入平滑、趋势、最短驻留和冷却。
- 优化地图扫描与缓存。
- 改进军事、经济和胜利里程碑指标。

### 阶段 2：竞争者选择

- 引入人类参考、世界分布和自身趋势。
- 区分能力健康度和胜利威胁度。
- 限制全局恢复名额与每个 AI 干预预算，保留文明差异。

### 阶段 3：支柱恢复执行器

- 分别验证扩张/人口、基础设施/改良、贸易/金币、科技、文化和防御。
- 为每个执行器建立“激活 -> 实际选择 -> 结果”的验证链。
- 删除无效或副作用大于收益的权重。

### 阶段 4：胜利与军事转化

- 科技：宇航中心、项目顺序和项目保护。
- 文化：巨作槽位、旅游来源、开放边境和国际贸易。
- 军事：单位角色、升级、行动编组、攻城和停战结果。
- 海图、远距离目标与空军单独测试。

### 阶段 5：可选难度配置

- 在 Decision-only 稳定后，再测试有限的静态难度曲线。
- 直接经济补助若存在，必须默认关闭、明确标注，并与行为效果分开报告。

## 6. 下一次代码修改的最小范围

下一次不应直接继续调高科技或文化权重。最小合理改动是阶段 0 与阶段 1 的基础：

1. 将检查起始、间隔、驻留和冷却换算成标准速度等效回合。
2. 把静态时代倍率改成可独立启用的模块或测试配置。
3. 在不改变策略结果的前提下记录平滑前后指标、世界分布和胜利里程碑。
4. 用固定种子确认日志、读档和性能，再决定新的阈值与权重。
